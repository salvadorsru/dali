# Dalí

**Local search and indexing engine for Figma `.fig` files.**

Dalí parses Figma `.fig` files, builds a local SQLite index, and exposes structural, full-text, and semantic search through a CLI and MCP server.

The `.fig` file remains the source of truth. Everything generated by Dalí is a rebuildable local index.

## ✨ Features

* **Local `.fig` parsing** — decode Figma's Kiwi binary format without requiring Figma to be open.
* **SQLite index** — persistent, rebuildable index stored under `.dali/`.
* **Structural search** — query the document tree and node relationships.
* **Full-text search** — powered by SQLite FTS5.
* **Semantic search** — vector search powered by `sqlite-vec`.
* **Local embeddings** — optional automatic embedding with `llama.cpp` and `EmbeddingGemma`.
* **Ollama support** — use an existing Ollama embedding server instead.
* **Remote embeddings** — support for remote embedding providers.
* **Incremental indexing** — only missing or changed embeddings need to be generated.
* **Design linting** — accessibility + design-quality checks with presets.
* **Geometry analysis** — layout gaps, repeated node sizes, sibling overlaps.
* **Component code generation** — generate HTML components with Tailwind or CSS variables, plus design tokens.
* **Name suggestions** — near-miss hints when a query or filter matches nothing.
* **MCP server** — expose one or multiple `.fig` files to MCP clients.
* **Multiple MCP clients** — configuration helpers for OpenCode, Cursor, Claude Code, VS Code, Cline, Roo Code, and Windsurf.
* **Asset extraction** — extract images next to the original `.fig` file.
* **CGo-free** — SQLite and `sqlite-vec` are provided through `modernc.org/sqlite`.

The project is deliberately split into parsing, modelling, indexing, querying, embedding, and MCP layers.

### Packages

| Package      | Responsibility                                      |
| ------------ | --------------------------------------------------- |
| `kiwi/`      | Kiwi schema decoding and dynamic message decoding   |
| `parser/`    | ZIP/chunk decompression and raw message parsing     |
| `model/`     | Build the document tree from `nodeChanges`          |
| `index/`     | SQLite schema, writes, FTS5, and vector storage     |
| `query/`     | Read-side query API and SQL ownership               |
| `embed/`     | Embedding interface and embedding providers         |
| `semantic/`  | Semantic text generation and incremental embeddings |
| `quality/`   | Design linting and geometry analysis                |
| `codegen/`   | HTML + Tailwind code generation (IR, generator, tokens) |
| `assets/`    | Image extraction                                    |
| `workspace/` | `.dali/` path layout                                |
| `output/`    | Output handling                                     |
| `mcp/`       | MCP server                                          |
| `cmd/dali/`  | CLI entry point                                     |

### Scope

The core is `kiwi/` → `parser/` → `model/` → `index/` → `query/`, plus `embed/`,
`semantic/`, `mcp/` and `cmd/dali/`. That is where correctness and performance
work belongs.

`quality/` and `codegen/` form a **peripheral perimeter**: they are maintained
and must keep working, but they are not the focus. Treat their output as frozen
— do not change their public behaviour unless the task explicitly asks for it,
and never let perimeter work reshape the core pipelines. Because they read `.fig`
through `parser.Open` + `model.Build` (see the conformance test in
`query/conformance_test.go`), a core model change can still surface there; keep
that path covered rather than reaching into these packages.

## 🔎 Search

Dalí provides three complementary ways to search an indexed design.

### Structural

The parsed Figma tree is preserved in SQLite, allowing queries based on nodes and their relationships. The `query` DSL accepts field predicates (`type=`, `name=`, `name~`, `text~`, `font=`, `page=`, `component=`, `visible=`, numeric `width`/`height`/`font_size`/`opacity` with `=`, `!=`, `>`, `>=`, `<`, `<=`) combined with `AND`, and named-node relations (`descendants()`, `ancestors()`, `children()`), plus a small XPath subset (`/`, `//`, `*`, `@name=`/`@name~`/`contains(@name,..)`); expressions starting with `/` are evaluated in-memory over the document tree by `query.XPath`. When a query matches nothing, token-scored near-miss names are offered via `query.SuggestNames` (search, query) and `query.SuggestXPath` (XPath).

### Full-text

SQLite FTS5 provides traditional text search over indexed content.

### Semantic

Semantic search generates embeddings for meaningful node text and stores them in a `sqlite-vec` vector index.

Nodes with automatically generated names and no text, such as `Vector` or `Frame 12`, are not embedded. They remain available for structural search.

```text
                 Search
                    │
        ┌───────────┼───────────┐
        │           │           │
   Structural      FTS5     Semantic
        │           │           │
        └───────────┼───────────┘
                    │
                 Results
```

## 🧠 Semantic Search

Semantic search uses an `Embedder` abstraction, allowing different embedding providers.

Supported providers:

```text
auto
ollama
llama
remote
```

The default `auto` provider manages an official `llama.cpp` `llama-server` using:

**`ggml-org/embeddinggemma-300M-GGUF`**

The model and server are downloaded into:

```text
~/.cache/dali
```

by default.

Downloads are confirmed before starting unless explicitly skipped.

The managed server is kept running so subsequent commands can reuse it.

### Configuration

| Variable                 | Purpose                                    |
| ------------------------ | ------------------------------------------ |
| `DALI_EMBED_PROVIDER`    | `auto`, `ollama`, `llama`, `remote`, or `off` |
| `DALI_EMBEDDINGS=1`      | Opt-in: enable embeddings in the MCP server |
| `DALI_CACHE_DIR`         | Dalí cache directory                       |
| `DALI_LLAMA_URL`         | Reuse an existing `llama-server`           |
| `DALI_EMBED_URL`         | Ollama embedding endpoint                  |
| `DALI_EMBED_YES=1`       | Skip download confirmation                 |
| `DALI_LLAMA_KEEP=0`      | Stop the managed server after each command |
| `DALI_LLAMA_PARALLEL`    | Override llama-server parallelism          |
| `DALI_LLAMA_THREADS`     | Override llama-server threads              |
| `DALI_EMBED_CONCURRENCY` | Embedding worker concurrency               |
| `DALI_EMBED_BATCH`       | Embedding batch size                       |
| `DALI_NET_TEST=1`        | Enable live network tests                  |
| `DALI_MANAGED_TEST=1`    | Enable managed-server tests                |

Embedding generation uses a worker pool and a single SQLite writer.

If the embedding model or `semantic.GeneratorVersion` changes, the vector index is rebuilt.

## 📁 Files

Dalí keeps the original `.fig` untouched.

Given:

```text
design.fig
```

technical files are stored under:

```text
.dali/
└── design.db
```

User-facing assets are stored next to the source file:

```text
design.assets/
└── images/
```

The SQLite database is a **rebuildable index**, not the source of truth.

Deleting `.dali/` therefore removes generated index data without modifying the original design.

## 🔌 MCP

Dalí includes an MCP server that can expose multiple `.fig` files from a single server.

MCP tools accept an optional `file` argument, and `list_figs` can discover available files.

Indexing is lazy when required.

Progress is reported through MCP progress notifications when the client provides a `_meta.progressToken`. Dalí also reports indexing activity through `dali:` lines on stderr.

### Embeddings opt-in

The MCP server constructs an embedder **only** when `DALI_EMBEDDINGS=1` is set
(`mcpEmbedder` in `mcp/server.go`); `DALI_EMBED_PROVIDER=off` also disables it.
Searches never build embeddings — `index_embeddings` is the only tool that
calls `ensureEmbedded`. Llama-server never starts at server open time; it
launches on the first actual `Embed` call.

| Tool | Embeddings | Indexes |
| --- | --- | --- |
| `section_figma`, `search_figma`, `query_figma`, `xpath_figma`, `find_components`, `find_instances` | never | never |
| `search_figma` — `mode=hybrid` | only when the vector index already exists and embeddings are ON | never (falls back to full-text) |
| `search_figma` — `mode=semantic` | only when embeddings are ON and the vector index exists | never |
| `index_embeddings` | yes | yes — the only tool that does |

Agent guidance: exact names → `section_figma` / `search_figma` (`mode=text`).
Do not use `semantic`/`hybrid` unless the query is conceptual. Hybrid uses
existing vectors only, and semantic fails with a hint when disabled or unindexed —
call `index_embeddings` first.

### MCP configuration

Generate configuration for supported clients with:

```bash
dali mcp-config --opencode
```

Available targets:

```text
--opencode
--cursor
--claude
--vscode
--cline
--roo
--windsurf
--all
```

`--all` generates configurations for all supported clients.

Existing configuration files are merged rather than blindly replaced.

| Client      | Configuration                         |
| ----------- | ------------------------------------- |
| OpenCode    | `opencode.json`                       |
| Cursor      | `.cursor/mcp.json`                    |
| Claude Code | `.mcp.json`                           |
| VS Code     | `.vscode/mcp.json`                    |
| Cline       | `.cline/mcp.json`                     |
| Roo Code    | `.roo/mcp.json`                       |
| Windsurf    | `~/.codeium/windsurf/mcp_config.json` |

## 🌱 Lint & Analyze

`quality/` parses the `.fig` through `parser.Open` + `model.Build` directly
(both CLI and MCP); it never reads the SQLite index, so results are never stale.

- `quality.Lint` runs rules under presets: `recommended` (default), `strict`
  (warn → error) and `accessibility` (accessibility rules only, all errors).
  Rules live in `quality/lint.go`; contrast helpers in `quality/color.go`.
- `quality.Analyze` covers `spacing` (layout gaps histogram), `clusters`
  (repeated node sizes) and `overlaps` (intersecting siblings). Colour and
  typography aggregation already lives in `query` (`get_tokens`) and must not
  be duplicated here.

## ⚙️ Component Code Generation

`dali <fig> generate` turns components and component sets into HTML + Tailwind.
`codegen/entry.go` drives the single `codegen/html.HTMLGenerator` directly; no
framework registry or per-framework generators exist.

```bash
dali design.fig generate                              # all components
dali design.fig generate --component 1:123 --out ./components
dali design.fig generate --tokens css
```

- `codegen/ir` holds the shared IR (`ComponentSpec`, `NodeSpec`, `LayoutSpec`,
  `StyleSpec`, `TextSpec`, `GeneratorConfig`).
- `codegen/util` translates `model` nodes into the IR (`TranslateLayout`,
  `TranslateStyles`, `TranslateText`, `BuildComponentSpec`) and emits Tailwind
  classes or CSS variables (`LayoutToTailwind`, `StyleToTailwind`,
  `TextToTailwind`, `LayoutToCSSVars`, `StyleToCSSVars`).
- `codegen/html` emits a self-contained HTML file per component from the IR;
  `codegen/tokens` exports tokens as CSS variables, Style Dictionary JSON
  or Figma Tokens JSON.
- Model node `Rotation` is already in degrees; do not re-convert radians.
- Text content emitted into HTML must be escaped, never interpolated raw, so
  strings like `-15%` stay valid.

## 🗄️ SQLite & FTS5

Dalí uses:

```text
modernc.org/sqlite v1.59.0
```

FTS5 is compiled into the dependency, so no build tag is required.

Older versions required:

```text
-tags sqlite_fts5
```

Do not downgrade the SQLite dependency without checking FTS5 support.

---

## 📐 Vector Search

`sqlite-vec` is provided through:

```text
modernc.org/sqlite/vec
```

It is CGo-free and automatically registered through a blank import.

The vector index uses:

```text
vec_nodes
```

with:

```text
node_id TEXT PRIMARY KEY
embedding float[N]
distance_metric=cosine
```

No separate database or driver is required.

## 📦 Project status

Dalí is designed around a local-first workflow:

* the `.fig` file stays local;
* the SQLite index is rebuildable;
* embeddings can run locally;
* Figma does not need to be open;
* CLI and MCP share the same query layer.

The goal is to make `.fig` files directly searchable and useful to local developer and AI tooling.
